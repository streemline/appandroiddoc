## README - Time Tracking System (Android)

### Опис

"Time Tracking System" - це сучасний мобільний застосунок для платформи Android, розроблений для ефективного обліку робочого часу. Застосунок дозволяє користувачам легко фіксувати час початку та закінчення роботи, додавати нотатки, переглядати статистику відпрацьованих годин, розраховувати заробітну плату (за наявності погодинної ставки) та експортувати дані у популярні формати (PDF, Excel, CSV).

### Основні можливості

* 📊 Зручний облік робочого часу: Легке додавання, редагування та видалення записів робочого часу.

* 📈 Детальна статистика: Перегляд статистики за поточний місяць, календарне відображення активності.

* 💰 Розрахунок заробітної плати: Автоматичний розрахунок на основі заданої погодинної ставки.

* 📤 Експорт даних: Експорт звітів у формати PDF, Excel та CSV для подальшого аналізу або звітності.

* 🎨 Сучасний інтерфейс: Інтуїтивно зрозумілий дизайн з анімаціями та інтерактивними елементами.

* ⚙️ Налаштування профілю: Встановлення імені користувача та погодинної ставки.

* 🌍 Локалізація: Підтримка української та англійської мов.

### Технології

* Мова розробки: Kotlin (або Java)

* Платформа: Android

* Архітектура: MVVM (Model-View-ViewModel)

* База даних: Локальна SQLite (через Room Persistence Library)

* Android Jetpack: ViewModel, LiveData, Room, Data Binding/View Binding, Navigation

* Бібліотеки для експорту: iTextPDF, Apache POI, вбудовані засоби CSV

### Інструкції з розгортання

1.  Переконайтеся, що на вашому комп'ютері встановлено Android Studio та необхідні Android SDK.

2.  Клонуйте репозиторій проєкту (якщо він є) або отримайте код в інший спосіб.

3.  Відкрийте проєкт в Android Studio (File > Open).

4.  Дочекайтеся завершення збірки проєкту Gradle (Gradle Sync).

5.  Запустіть застосунок на емуляторі Android або фізичному Android-пристрої (Run > Run 'app').

### Інструкції з використання

1.  Головний екран (Статистика): Відображає статистику за поточний місяць та список останніх записів. Натисніть кнопку "+" для додавання нової записи.

2.  Додавання запису: У формі введіть дату, час початку, час закінчення та (за бажанням) нотатки. Натисніть "Зберегти".

3.  Редагування запису: Натисніть на існуючу запис у списку для її редагування. Внесіть зміни та натисніть "Зберегти".

4.  Профіль: Перейдіть на сторінку профілю (зазвичай через меню або навігаційну панель) для зміни імені та погодинної ставки.

5.  Експорт: Перейдіть на сторінку експорту (може бути в меню або на сторінці статистики). Оберіть формат (PDF, Excel, CSV) та період для експорту. Запустіть експорт. Експортований файл буде збережено у внутрішньому сховищі пристрою.

**1. Загальна архітектура**

Застосунок розроблено з використанням архітектурного патерну **MVVM (Model-View-ViewModel)**, що сприяє розділенню відповідальності між UI-елементами, логікою представлення та даними.

* **Model:** Шар даних, що відповідає за зберігання та отримання даних. У цьому проєкті представлений Entity-класами (наприклад, User, TimeEntry) та локальною базою даних (SQLite через Room Persistence Library).

* **View:** Шар представлення, що відображає дані користувачеві та обробляє його дії. Представлений Activity, Fragments та Layout-файлами.

* **ViewModel:** Шар логіки представлення, що надає дані для View та обробляє дії користувача, не маючи прямого посилання на View. ViewModel отримує дані з Repository та надає їх у форматі LiveData для спостереження View.

**3. Ключові компоненти та їх призначення**

* **Data Layer com.example.timetracker.data)**:

    * *local**: Відповідає за роботу з локальною базою даних SQLite через Room.

        * *dao**: Містить інтерфейси DAO TimeEntryDao, UserDao) для виконання CRUD-операцій з таблицями time_entries та users. Використовує анотації Room @Query, @Insert, @Update, @Delete).

        * *db**: Містить клас AppDatabase, який є абстрактним класом, що розширює RoomDatabase та надає доступ до DAO-інтерфейсів. Єдиний екземпляр бази даних створюється за допомогою Singleton-патерну.

        * *model**: Містить Entity-класи TimeEntry, User, MonthlyReport), які представляють таблиці бази даних. Анотовані @Entity для визначення їх як таблиць Room.

    * *repository**: Містить класи репозиторіїв TimeEntryRepository, UserRepository), які виступають посередниками між ViewModel та джерелами даних (локальна база даних, а в майбутньому - мережа). Репозиторії інкапсулюють логіку отримання та маніпулювання даними. Використовують DAO для взаємодії з базою даних та класи експорту ExcelExporter, PdfExporter, CSVExporter).

* **UI Layer com.example.timetracker.ui)**:

    * *components**: Містить кастомні UI-компоненти, які використовуються у фрагментах для відображення анімацій та специфічних елементів інтерфейсу AnimatedVisibilityComponent, AnimatedListComponent, FadeOutAnimationComponent, MonthCardComponent).

    * *input**: Містить фрагмент InputTimeEntryFragment для додавання та редагування записів робочого часу.

    * *main**: Містить основну активність MainActivity, яка відповідає за навігацію між фрагментами.

    * *profile**: Містить фрагмент ProfileFragment для відображення та редагування профілю користувача.

    * *statistics**: Містить фрагмент StatisticsFragment для відображення статистики робочого часу та адаптер TimeEntryAdapter для відображення списку записів у RecyclerView.

* **ViewModel Layer com.example.timetracker.viewmodel)**:

    * Містить класи ViewModel TimeEntryViewModel, UserViewModel), які готують та надають дані для UI-елементів у форматі LiveData. ViewModel не містять логіки UI та переживають зміни конфігурації Activity/Fragment. Вони отримують дані з репозиторіїв та надають їх для спостереження View.

* **Utils Layer com.example.timetracker.utils)**:

    * Містить утилітарні класи, такі як DateUtils для роботи з датами та часом, а також класи для експорту даних у різні формати ExcelExporter, PdfExporter, CSVExporter).

2. Загальний опис

2.1. Опис продукту:

"Time Tracking System" - це сучасний та інтуїтивно зрозумілий мобільний застосунок для Android, що дозволяє користувачам ефективно відстежувати свій робочий час. Застосунок надає функціонал для додавання, редагування та видалення записів робочого часу, автоматично розраховує тривалість роботи та заробітну плату (за наявності погодинної ставки), відображає статистику у зручному форматі та дозволяє експортувати дані для подальшого аналізу або звітності.

2.2. Характеристики користувачів:

* Фрілансери: Потребують точного обліку часу для виставлення рахунків клієнтам.

* Працівники з погодинною оплатою: Необхідно відстежувати відпрацьовані години для нарахування заробітної плати.

* Співробітники компаній: Для особистого обліку продуктивності та контролю робочого часу.

* Технічно обізнані користувачі: Очікують сучасний інтерфейс та зручну навігацію.

2.3. Операційне середовище:

* Платформа: Android (мінімальна підтримувана версія API буде визначена на етапі планування розробки).

* Підключення до мережі: Не обов'язкове для основного функціоналу обліку часу, але може бути необхідним для майбутніх функцій (наприклад, синхронізації з хмарою).

2.4. Обмеження:

* Застосунок є мобільним і працює лише на платформі Android.

* Перша версія не передбачає командної роботи або синхронізації даних між пристроями.

3. Функціональні вимоги

3.1. FR1: Облік робочого часу:

    * Користувач повинен мати можливість додавати нові записи робочого часу з зазначенням:

        * Дати (обов'язково).

        * Часу початку (обов'язково).

        * Часу закінчення (обов'язково).

        * Нотаток (необов'язково).

    * Система повинна автоматично розраховувати тривалість кожної записи на основі часу початку та закінчення.

    * Користувач повинен мати можливість редагувати існуючі записи робочого часу (зміна дати, часу, нотаток).

    * Користувач повинен мати можливість видаляти існуючі записи робочого часу.

    * Система повинна відображати список усіх записів робочого часу, відсортованих за датою та часом (за замовчуванням - останні зверху).

    * Система повинна надавати можливість перегляду детальної статистики за обраний день (список записів за цей день, загальна тривалість).

3.3. FR3: Розрахунок заробітної плати:

     Система повинна автоматично розраховувати заробітну плату за кожну запис робочого часу (тривалість у годинах  погодинна ставка).

    * Система повинна відображати загальну розраховану заробітну плату за обраний період (поточний місяць, обраний день у детальній статистиці).

        * Загальну кількість відпрацьованих годин за обраний період.

        * (Якщо задано погодинну ставку) Загальну розраховану заробітну плату за обраний період.

        * Інформацію про користувача (ім'я з профілю).

    * Користувач повинен мати можливість експортувати дані про робочий час у формат Excel (XLSX). Експортований файл повинен містити таблицю з даними про записи робочого часу (дата, час початку, час закінчення, тривалість, нотатки, розрахована заробітна плата, якщо задано ставку).

    * Користувач повинен мати можливість експортувати дані про робочий час у формат CSV. Експортований файл повинен містити дані про записи робочого часу, розділені комами (дата, час початку, час закінчення, тривалість, нотатки, розрахована заробітна плата, якщо задано ставку).

    * Користувач повинен мати можливість обирати період для експорту даних (поточний місяць, попередній місяць, діапазон дат).

3.5. FR5: Профіль користувача:

3.6. FR6: Інтерфейс користувача:

5. Зовнішні інтерфейси

5.1. Інтерфейс користувача (UI):

    * Сучасний графічний інтерфейс, розроблений відповідно до принципів Material Design.

    * Використання стандартних UI-компонентів Android, а також кастомних анімованих компонентів.

5.2. Апаратні інтерфейси:

    * Використання стандартних API Android для доступу до системних функцій (наприклад, файлової системи для експорту).

    * Адаптивний дизайн для коректного відображення на екранах різних розмірів та орієнтацій.

5.3. Програмні інтерфейси:

    * Використання бібліотек Room Persistence Library для взаємодії з локальною базою даних SQLite.

    * Використання зовнішніх бібліотек для створення PDF (наприклад, iTextPDF), Excel (наприклад, Apache POI) та CSV (вбудовані засоби Java/Kotlin або сторонні бібліотеки).

6. Інші вимоги

6.1. Локалізація:

    * Перша версія повинна підтримувати як мінімум українську та англійську мови.

    * Усі текстові елементи інтерфейсу повинні бути винесені в файли ресурсів для полегшення локалізації.

7. Вимоги до тестування

7.1. Unit-тестування:

    * Покриття ключової бізнес-логіки (наприклад, розрахунок тривалості, розрахунок заробітної плати) юніт-тестами.

    * Тестування окремих компонентів ViewModel та утилітарних класів.

7.2. Інтеграційне тестування:

    * Перевірка взаємодії між різними шарами застосунку (UI - ViewModel - Repository - Database).

    * Тестування процесів додавання, редагування та видалення даних.

    * Перевірка функціональності експорту даних у різних форматах.

7.3. UI-тестування:

    * Перевірка коректності відображення інтерфейсу користувача та навігації.

    * Тестування реакції інтерфейсу на дії користувача.

    * Перевірка валідації форм введення даних.

7.4. Ручне тестування:

    * Проведення всебічного ручного тестування на реальних пристроях або емуляторах для виявлення проблем, які можуть не бути виявлені автоматизованими тестами.

8. Майбутній розвиток

* Синхронізація даних між пристроями.

* Веб-інтерфейс для перегляду та управління даними.

* Командний облік робочого часу.

* Інтеграція з іншими сервісами.

* Розширені можливості статистики та звітності.
