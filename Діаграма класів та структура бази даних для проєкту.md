## Діаграма класів та структура бази даних для проєкту "Time Tracking System"

### 1. Діаграма класів (спрощена)

```plantuml
@startuml
package com.example.timetracker {
  class MainActivity
  class InputTimeEntryFragment
  class StatisticsFragment
  class ProfileFragment
  class TimeEntryViewModel
  class UserViewModel
  class TimeEntryRepository
  class UserRepository
  interface TimeEntryDao
  interface UserDao
  class AppDatabase
  class TimeEntry
  class User
  class MonthlyReport
  class DateUtils
  class ExcelExporter
  class PdfExporter
  class CSVExporter
  class AnimatedVisibilityComponent
  class AnimatedListComponent
  class FadeOutAnimationComponent
  class MonthCardComponent

  MainActivity --|> InputTimeEntryFragment
  MainActivity --|> StatisticsFragment
  MainActivity --|> ProfileFragment

  InputTimeEntryFragment -- TimeEntryViewModel
  StatisticsFragment -- TimeEntryViewModel
  ProfileFragment -- UserViewModel

  TimeEntryViewModel -- TimeEntryRepository
  UserViewModel -- UserRepository

  TimeEntryRepository -- TimeEntryDao
  UserRepository -- UserDao

  TimeEntryDao -- AppDatabase
  UserDao -- AppDatabase

  TimeEntryRepository -- TimeEntry
  UserRepository -- User

  StatisticsFragment -- MonthCardComponent

  TimeEntryViewModel -- DateUtils
  StatisticsFragment -- DateUtils

  TimeEntryRepository -- ExcelExporter
  TimeEntryRepository -- PdfExporter
  TimeEntryRepository -- CSVExporter

  StatisticsFragment --|> AnimatedVisibilityComponent
  StatisticsFragment --|> AnimatedListComponent
  StatisticsFragment --|> FadeOutAnimationComponent

  InputTimeEntryFragment --|> AnimatedVisibilityComponent
  // ... інші зв'язки для анімацій ...
}
@enduml
```

**Опис класів:**

* **MainActivity:** Основна активність, що керує навігацією між фрагментами.
* **InputTimeEntryFragment:** Фрагмент для введення та редагування записів робочого часу.
* **StatisticsFragment:** Фрагмент для відображення статистики та місячних звітів.
* **ProfileFragment:** Фрагмент для відображення та редагування профілю користувача.
* **TimeEntryViewModel:** ViewModel для керування даними про записи робочого часу.
* **UserViewModel:** ViewModel для керування даними про користувача.
* **TimeEntryRepository:** Репозиторій для доступу до даних про записи робочого часу з бази даних.
* **UserRepository:** Репозиторій для доступу до даних про користувачів з бази даних.
* **TimeEntryDao:** Data Access Object (DAO) для таблиці `TimeEntries`.
* **UserDao:** Data Access Object (DAO) для таблиці `Users`.
* **AppDatabase:** Клас, що представляє локальну базу даних (Room Database).
* **TimeEntry:** Entity-клас, що відображає таблицю `TimeEntries`.
* **User:** Entity-клас, що відображає таблицю `Users`.
* **MonthlyReport:** Entity-клас, що відображає таблицю `MonthlyReports` (може бути реалізовано пізніше).
* **DateUtils:** Клас з утилітними функціями для роботи з датами.
* **ExcelExporter:** Клас для експорту даних у формат Excel.
* **PdfExporter:** Клас для експорту даних у формат PDF.
* **CSVExporter:** Клас для експорту даних у формат CSV.
* **AnimatedVisibilityComponent:** Компонент для анімації видимості елементів.
* **AnimatedListComponent:** Компонент для анімації списків.
* **FadeOutAnimationComponent:** Компонент для анімації згасання.
* **MonthCardComponent:** UI-компонент для відображення місячної статистики.

**Зв'язки:**

* Активності керують фрагментами.
* Фрагменти використовують ViewModel для отримання та керування даними.
* ViewModel використовують Repository для взаємодії з даними (база даних, мережа тощо).
* Repository використовують DAO для виконання операцій з базою даних.
* DAO взаємодіють з класом бази даних (Room Database).
* ViewModel та Repository використовують утилітарні класи (DateUtils, Exporters).
* Фрагменти використовують UI-компоненти.

### 2. Структура бази даних (описана в Технічному завданні)

```
Database: time_tracker_database

Tables:

1. Users
   Columns:
      - userId (INTEGER, PRIMARY KEY, AUTOINCREMENT)
      - name (TEXT, NOT NULL)
      - hourlyRate (REAL, DEFAULT 0.0)
      - settings (TEXT, JSON формат для зберігання додаткових налаштувань)

2. TimeEntries
   Columns:
      - entryId (INTEGER, PRIMARY KEY, AUTOINCREMENT)
      - userId (INTEGER, NOT NULL, FOREIGN KEY REFERENCES Users(userId))
      - date (TEXT, NOT NULL, формат YYYY-MM-DD)
      - startTime (TEXT, NOT NULL, формат HH:MM)
      - endTime (TEXT, NOT NULL, формат HH:MM)
      - duration (INTEGER, NOT NULL, кількість хвилин)
      - notes (TEXT)

3. MonthlyReports (може бути реалізовано пізніше)
   Columns:
      - reportId (INTEGER, PRIMARY KEY, AUTOINCREMENT)
      - userId (INTEGER, NOT NULL, FOREIGN KEY REFERENCES Users(userId))
      - month (TEXT, NOT NULL, формат YYYY-MM)
      - totalHours (REAL, NOT NULL)
      - totalSalary (REAL, NOT NULL)

Індекси:
- Рекомендується створити індекс для стовпця `userId` у таблиці `TimeEntries` для оптимізації запитів, пов'язаних з конкретним користувачем.
  ```sql
  CREATE INDEX index_timeentries_userid ON TimeEntries (userId);
  ```
- За необхідності, можна додати індекси для стовпця `date` у таблиці `TimeEntries` для оптимізації фільтрації за датою.

**Зв'язки між таблицями:**

* Таблиця `TimeEntries` має зовнішній ключ `userId`, який посилається на первинний ключ `userId` таблиці `Users`. Це забезпечує зв'язок "один-до-багатьох" між користувачами та їхніми записами робочого часу (один користувач може мати багато записів).
* Таблиця `MonthlyReports` (якщо буде реалізована) також матиме зовнішній ключ `userId`, що посилається на таблицю `Users`, забезпечуючи зв'язок між користувачами та їхніми місячними звітами.

Ці діаграма класів та структура бази даних надають загальне уявлення про організацію коду та зберігання даних у вашому проєкті "Time Tracking System". Вони можуть бути деталізовані та змінені в процесі розробки відповідно до конкретних потреб.
