## Специфікація вимог до програмного забезпечення (SRS) - "Time Tracking System"

**Версія:** 1.0
**Дата:** 14 квітня 2025

**1. Вступ**

1.1. **Мета документу:**
Цей документ є специфікацією вимог до програмного забезпечення (SRS) для мобільного застосунку "Time Tracking System" на платформі Android. Він описує функціональні та нефункціональні вимоги до системи, які будуть використані як основа для розробки, тестування та документування застосунку.

1.2. **Цільова аудиторія:**
Цей документ призначений для наступних осіб та команд:
* Розробники програмного забезпечення
* Тестувальники програмного забезпечення
* Менеджери проєкту
* Зацікавлені сторони

1.3. **Область застосування:**
Мобільний застосунок "Time Tracking System" призначений для обліку робочого часу користувачів, відстеження статистики, управління часовими записами та експорту даних у різні формати на пристроях з операційною системою Android.

**2. Загальний опис**

2.1. **Опис продукту:**
"Time Tracking System" - це сучасний та інтуїтивно зрозумілий мобільний застосунок для Android, що дозволяє користувачам ефективно відстежувати свій робочий час. Застосунок надає функціонал для додавання, редагування та видалення записів робочого часу, автоматично розраховує тривалість роботи та заробітну плату (за наявності погодинної ставки), відображає статистику у зручному форматі та дозволяє експортувати дані для подальшого аналізу або звітності.

2.2. **Характеристики користувачів:**
* **Фрілансери:** Потребують точного обліку часу для виставлення рахунків клієнтам.
* **Працівники з погодинною оплатою:** Необхідно відстежувати відпрацьовані години для нарахування заробітної плати.
* **Співробітники компаній:** Для особистого обліку продуктивності та контролю робочого часу.
* **Технічно обізнані користувачі:** Очікують сучасний інтерфейс та зручну навігацію.

2.3. **Операційне середовище:**
* **Платформа:** Android (мінімальна підтримувана версія API буде визначена на етапі планування розробки).
* **Підключення до мережі:** Не обов'язкове для основного функціоналу обліку часу, але може бути необхідним для майбутніх функцій (наприклад, синхронізації з хмарою).

2.4. **Обмеження:**
* Застосунок є мобільним і працює лише на платформі Android.
* Перша версія не передбачає командної роботи або синхронізації даних між пристроями.

**3. Функціональні вимоги**

3.1. **FR1: Облік робочого часу:**
    * Користувач повинен мати можливість додавати нові записи робочого часу з зазначенням:
        * Дати (обов'язково).
        * Часу початку (обов'язково).
        * Часу закінчення (обов'язково).
        * Нотаток (необов'язково).
    * Система повинна автоматично розраховувати тривалість кожної записи на основі часу початку та закінчення.
    * Користувач повинен мати можливість редагувати існуючі записи робочого часу (зміна дати, часу, нотаток).
    * Користувач повинен мати можливість видаляти існуючі записи робочого часу.
    * Система повинна відображати список усіх записів робочого часу, відсортованих за датою та часом (за замовчуванням - останні зверху).

3.2. **FR2: Статистика:**
    * Система повинна відображати статистику за поточний місяць на головному екрані:
        * Загальну кількість відпрацьованих годин.
        * Список останніх (кількість буде визначено) записів робочого часу.
    * Система повинна надавати можливість перегляду статистики за попередні місяці.
    * Система повинна відображати календар з візуальним позначенням днів, у які були внесені записи робочого часу.
    * Система повинна надавати можливість перегляду детальної статистики за обраний день (список записів за цей день, загальна тривалість).

3.3. **FR3: Розрахунок заробітної плати:**
    * Користувач повинен мати можливість задати свою погодинну ставку у налаштуваннях профілю.
    * Система повинна автоматично розраховувати заробітну плату за кожну запис робочого часу (тривалість у годинах * погодинна ставка).
    * Система повинна відображати загальну розраховану заробітну плату за обраний період (поточний місяць, обраний день у детальній статистиці).

3.4. **FR4: Експорт даних:**
    * Користувач повинен мати можливість експортувати дані про робочий час у формат PDF. Експортований файл повинен містити:
        * Таблицю з усіма записами робочого часу за обраний період (дата, час початку, час закінчення, тривалість, нотатки).
        * Загальну кількість відпрацьованих годин за обраний період.
        * (Якщо задано погодинну ставку) Загальну розраховану заробітну плату за обраний період.
        * Інформацію про користувача (ім'я з профілю).
    * Користувач повинен мати можливість експортувати дані про робочий час у формат Excel (XLSX). Експортований файл повинен містити таблицю з даними про записи робочого часу (дата, час початку, час закінчення, тривалість, нотатки, розрахована заробітна плата, якщо задано ставку).
    * Користувач повинен мати можливість експортувати дані про робочий час у формат CSV. Експортований файл повинен містити дані про записи робочого часу, розділені комами (дата, час початку, час закінчення, тривалість, нотатки, розрахована заробітна плата, якщо задано ставку).
    * Користувач повинен мати можливість обирати період для експорту даних (поточний місяць, попередній місяць, діапазон дат).

3.5. **FR5: Профіль користувача:**
    * Користувач повинен мати можливість переглядати та редагувати своє ім'я.
    * Користувач повинен мати можливість задати та редагувати свою погодинну ставку (числове значення).

3.6. **FR6: Інтерфейс користувача:**
    * Застосунок повинен мати сучасний та інтуїтивно зрозумілий інтерфейс відповідно до принципів Material Design.
    * Повинна бути забезпечена зручна навігація між основними сторінками (статистика, профіль, експорт).
    * Форми для введення даних повинні мати валідацію (наприклад, перевірка коректності формату часу).
    * Повинні бути використані анімаційні переходи та інтерактивні елементи для покращення UX.
    * Застосунок повинен підтримувати світлу тему оформлення.

**4. Нефункціональні вимоги**

4.1. **NV1: Продуктивність:**
    * Застосунок повинен запускатися не довше ніж за 3 секунди.
    * Операції додавання, редагування та видалення записів повинні виконуватися миттєво (не більше 1 секунди).
    * Відображення статистики повинно відбуватися швидко (не більше 2 секунд).
    * Експорт даних для невеликих обсягів (до 100 записів) не повинен займати більше 5 секунд.

4.2. **NV2: Надійність:**
    * Застосунок не повинен аварійно завершувати роботу під час звичайного використання.
    * Дані користувача повинні зберігатися локально та бути доступними після перезапуску застосунку.

4.3. **NV3: Зручність використання (Usability):**
    * Інтерфейс застосунку повинен бути інтуїтивно зрозумілим для цільової аудиторії.
    * Основні функції повинні бути легкодоступними.
    * Повинні бути надані зрозумілі повідомлення про помилки та успішні операції.

4.4. **NV4: Підтримуваність:**
    * Кодова база повинна бути добре структурованою та містити коментарі для полегшення подальшої підтримки та розширення.
    * Використання архітектурного патерну (наприклад, MVVM) сприятиме поділу відповідальності та полегшить тестування.

4.5. **NV5: Безпека:**
    * Локальні дані користувача повинні бути захищені від несанкціонованого доступу на рівні операційної системи.

**5. Зовнішні інтерфейси**

5.1. **Інтерфейс користувача (UI):**
    * Сучасний графічний інтерфейс, розроблений відповідно до принципів Material Design.
    * Використання стандартних UI-компонентів Android, а також кастомних анімованих компонентів.

5.2. **Апаратні інтерфейси:**
    * Використання стандартних API Android для доступу до системних функцій (наприклад, файлової системи для експорту).
    * Адаптивний дизайн для коректного відображення на екранах різних розмірів та орієнтацій.

5.3. **Програмні інтерфейси:**
    * Використання бібліотек Room Persistence Library для взаємодії з локальною базою даних SQLite.
    * Використання зовнішніх бібліотек для створення PDF (наприклад, iTextPDF), Excel (наприклад, Apache POI) та CSV (вбудовані засоби Java/Kotlin або сторонні бібліотеки).
